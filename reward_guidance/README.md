# C1 탐지기를 보상으로 쓸 수 있는가

`xattn_detector` 에서 얻은 C1 탐지기(미학습 task macro AUROC **0.891**)를 π0.5 의 denoising 샘플러에
reward guidance 로 연결하고, 그것이 실제로 C1 을 줄이는지 측정한다.

탐지기를 보상으로 바꾸는 일은 성능을 조금 더 올리는 문제가 아니라 **질문이 바뀌는** 문제다.
0.891 은 "서로 다른 두 순간 중 어느 쪽이 곧 빈 그리퍼를 닫는가"를 맞힌다는 뜻이다. guidance 는 그보다
엄격한 것을 요구한다 — **한 순간 안에서, 관측을 고정한 채, 정책이 뽑은 후보 행동들을 위험 순으로 줄 세울 것.**
이 저장소의 이전 단계에서 pooled AUROC 0.73 이 macro 0.50 이었던 것과 같은 종류의 혼동이 한 층 아래에서
반복될 수 있는 자리다. 그래서 네 단계로 나눠 측정했다.

모든 실험은 탐지기가 **학습에 쓰지 않은 4개 task** (`libero_spatial/t9`, `libero_object/t6`,
`libero_object/t0`, `libero_goal/t2`) 의 init 30–39, 40 에피소드에서 돈다.

## 0b. 분기(branch)가 무엇을 바꾸고 무엇을 바꾸지 않는가

`snapshot()/restore()` 로 한 상태에서 여러 행동을 실행해 보는 것이 이 실험 전체의 토대라, 먼저 검증했다.

* **물리는 정확히 재현된다.** 같은 snapshot 에서 같은 chunk 를 두 번 실행하면 `qpos`, `site_xpos` 가
  **비트 단위로 같다**(Δ = 0.0). 분기를 8번 한 뒤 본 궤적을 이어가도 물리는 분기하지 않은 경우와 동일하다.
* **관측 보고값은 재현되지 않는다.** robosuite 가 돌려주는 `robot0_eef_pos` 는 분기 후 실제 위치와
  최대 4.7e-3 m 어긋난다(분기 없을 때 4.8e-4 m). 제어 한 스텝 이동량 정도다. observable 파이프라인이
  snapshot 이 담지 않는 샘플링 위상을 들고 있기 때문이다.
* **따라서** 분기 라벨은 정확하고(물리), 분기한 rollout 은 분기하지 않은 rollout 과 정확히 같지는 않다
  (정책이 읽는 고유수용감각이 미세하게 흐려진다). Stage A·B 는 호출 안에서만 비교하므로 영향이 없고,
  Stage C 는 모든 arm 이 같은 snapshot 을 공유하므로 영향이 없다.
* 같은 chunk 를 다시 실행했을 때 라벨이 뒤집히는 비율 = **0.6% (5/841)**. 이것이 잡음 바닥이고,
  아래의 모든 "갈린다" 는 이 값과 비교해 읽어야 한다. (`opening` 이 0.04 m 문턱 바로 위아래일 때만 뒤집힌다.)

이 관측 위상 문제는 이전 단계에서 설명되지 않은 채 남아 있던 **교차 프로세스 재현 불일치**와 같은 뿌리로 보인다.

## 1. 고정 head (`detector.py`)

이전 단계는 교차검증 fold 마다 탐지기를 다시 학습했다. 일반화를 재는 데는 맞지만 조종에는 쓸 수 없다 —
rollout 에는 **하나의 고정된 w** 가 필요하다. 16개 task group 으로 학습하고 위 4개를 남겼다.

```
표본 4,994   양성 353 (7.1%)   학습 4,264 (양성 226)
미학습 4개 task:  goal/t2 0.978   object/t0 0.840   object/t6 0.930   spatial/t9 0.830
                  macro 0.894   (정식 교차검증 값 0.891±0.010 과 일치)
```

특징은 그대로 `suf_mean`(1024-D), 목표도 그대로 "앞으로 10 env step 안에 C1 onset". 10 step 은 chunk 하나의
실행 구간과 정확히 같아서, **라벨은 지금 채점하는 바로 그 chunk 가 만들어 낸다**. 이것이 이 head 를
감시자가 아니라 보상 후보로 볼 수 있는 이유다.

## 2. Stage A — 같은 상태에서 행동을 줄 세우는가 (`sensitivity.py`)

C1 이 아직 아닌 호출마다 π0.5 에서 chunk 8개를 뽑고(후보 0 = 원래 실행될 chunk, 그래서 궤적은 그대로),
각각을 고정 head 로 채점한 뒤 **같은 snapshot 에서 실제로 실행해** 시뮬레이터의 C1 술어로 라벨을 붙였다.
841 호출 × 8 후보 + 복제 대조군 = 분기 6,728회.

```
후보들이 결과를 달리하는 호출      5.9%  [4.5%, 7.5%]      (잡음 바닥 0.6%)
  전부 C1  10.6%        전부 안전  83.5%

상태 내 AUROC (head)              0.786 [0.689, 0.866]
상태 간 macro AUROC (대조)        0.930
```

**상태를 고정하면 상태 특징은 후보끼리 완전히 같아서 AUROC 가 정의상 0.500 이다.** 그러므로 0.786 은 전부
행동 정보다. 대조군은 행동에서 공짜로 읽히는 양이어야 한다:

| 상태 내 AUROC | |
|---|---|
| C1 head (1024-D 잠재변수) | 0.786 [0.689, 0.866] |
| **chunk 의 그리퍼 명령 평균 (스칼라 1개)** | **0.794 [0.709, 0.872]** |
| 그리퍼 닫힘 명령 비율 | 0.787 [0.715, 0.855] |
| 수직 이동 명령 평균 | 0.205 → 뒤집으면 0.795 |
| head − 그리퍼 명령 평균 | **−0.009 [−0.085, +0.070]** |

→ **같은 상태 안에서 head 가 하는 일은 chunk 의 그리퍼 채널 하나와 구별되지 않는다.**

best-of-8 로 쓰면: C1 발생률 13.2% → 11.5%, oracle 하한 10.6%, 무작위 선택 13.2%.
위험한 호출 111개 중 안전한 후보가 **존재하기라도 한** 경우가 19.8% 뿐 — 천장이 낮은 것은 탐지기가 아니라
**정책의 후보 다양성**이다.

## 3. Stage B — 기울기는 어디를 가리키는가 (`grad_probe.py`)

head 는 `suf_mean`(denoising 10 스텝 평균) 으로 학습되어 chunk 에 대한 기울기가 없다. 미분 가능한 대역은
행동 전문가를 한 번 더 통과시키는 것: `phi_eval(x1) = pooled suffix hidden at denoise_step(x_t=x1, t=1/K)`.

```
phi_eval ↔ suf_mean   호출 간 r = +0.949   상태 내 r = +0.793
상태 간 macro AUROC   suf_mean 0.908   phi_eval 0.885      → 대역으로 쓸 수 있다

기울기 에너지  회전 54.5%  그리퍼 27.1%(균등 기대 14.3%)  병진 18.4%(기대 42.9%)
cos(위험↓ 기울기, 안전 방향)      −0.146 [−0.217, −0.077]
cos("그리퍼를 열어라", 안전 방향)  +0.227 [+0.104, +0.345]
cos(무작위 방향, 안전 방향)        +0.017 [−0.023, +0.058]
```

**이 cos 는 Stage C 를 예측하지 못했다.** 기울기가 안전 방향의 반대를 가리킨다고 읽었지만, 실제 인과 측정은
반대로 나왔다. 측정이 좁았던 탓으로 본다 — 25개 호출, 그리고 (50,32) 기울기를 (10,7) 로 투영한 값,
"안전 방향"도 표본 후보 8개의 평균 차이라는 거친 추정량이다. **국소 선형 대리값으로 인과를 대신하지 말 것.**

## 4. Stage C — 실제로 C1 을 줄이는가 (`stage_c.py`, `guided.py`)

닫힌 루프 비교(개입 on/off 로 에피소드를 돌려 C1 율을 비교)는 이 질문의 **약한** 형태다. guided 와 unguided
rollout 은 첫 호출 이후 갈라지므로 비교는 에피소드 집합 사이의 비교가 되고, 40 에피소드에 담긴 C1 사건은
수십 개뿐이다. 대신 **호출마다 짝을 지었다**: 같은 상태·같은 시작 노이즈를 6갈래로 denoise 하고 전부
같은 snapshot 에서 실행한다. 844 호출 × 6 = 짝지은 사중비교.

보상은 `head(phi_eval(x1))`, 샘플러는 `pi05_steer.denoise` 와 동일한 Euler flow 에 단위 정규화 기울기를
`(λ/K)` 씩 더하는 방식(내장 hook 은 보상에 chunk 의 앞 16 스텝 7차원만 넘겨서 행동 전문가를 돌릴 수 없어
`guided.py` 에 샘플러를 따로 썼다). λ 는 **π0.5 자신의 재표집이 chunk 를 옮기는 거리**(정규화 공간 중앙값
0.757) 에 맞췄다. 무작위 대조군은 **그 arm 자신의 기울기 성분 부호만 뒤섞어** 크기 분포를 똑같이 맞췄다 —
등방 정규분포 방향은 실행되는 구간을 절반밖에 못 옮겨서 "guidance 가 더 멀리 갔을 뿐"이 섞인다.

| arm | 변위 | ΔC1 logit | C1 발생률 | Δ발생률 (95% CI) |
|---|---|---|---|---|
| 무개입 | 0.000 | — | 14.3% | — |
| 위험↓ λ10 | 1.221 | **−1.42** | 13.4% | **−0.95% [−1.76, −0.23]** |
| 위험↑ λ10 | 1.486 | **+1.72** | 15.8% | **+1.42% [+0.12, +2.77]** |
| 무작위 λ10 | 0.963 | +0.08 | 14.0% | −0.36% [−1.28, +0.48] |
| 위험↓ λ30 | 3.092 | −3.49 | 12.0% | −2.37% [−3.64, −1.25] |
| 무작위 λ30 | 2.973 | +0.95 | 11.0% | **−3.32% [−5.01, −1.82]** |

결정적인 두 대비:

```
부호 뒤집기 (λ10)   위험↓ − 위험↑      −2.37% [−3.96, −0.95]   → 기울기의 부호가 결과를 바꾼다
같은 보폭 (λ10)     위험↓ − 무작위     −0.59% [−1.45, +0.23]   → 구분되지 않는다
같은 보폭 (λ30)     위험↓ − 무작위     +0.95% [−0.60, +2.67]   → 구분되지 않는다
```

## 5. Stage D — 상태 내 질문으로 직접 학습하면 (`rank_head.py`)

Stage A 의 0.786 은 **상태 사이**의 판별로 학습된 head 를 상태 **안**에서 채점한 값이다. 그 head 는
이 질문으로 학습된 적이 없으므로, 질문을 바꿔 직접 학습했을 때 그리퍼 스칼라를 넘는지가 남은 물음이다.

**모형은 일부러 선형이다.** `f(phi) = w · phi` 면

```
f(위험) - f(안전) = w · (phi_위험 - phi_안전)
```

이라 상태 자신의 오프셋이 정확히 상쇄된다. 즉 이 head 는 상태 간 정보를 **구조적으로 쓸 수 없다**.
비선형 head 는 이 성질을 잃고 이미 답한 질문을 되불러온다.

세 변형을 하나의 교차검증 안에서 비교했다.

| 변형 | 입력 |
|---|---|
| `raw` | phi 의 상태 내 편차 전체 (1024-D), L2 |
| `pca` | 학습 폴드의 상태 내 편차로 적합한 상위 k개 PC (k ∈ {5,10,20,40}) |
| `resid` | phi 편차에서 **그리퍼 명령 방향을 회귀로 제거**한 나머지 |

`resid` 가 결정적이다 — phi 가 스칼라 하나 말고 무엇을 더 담고 있는지를 직접 묻는다.
분할은 **과제 LOGO 4폴드**(1순위, 미학습 task 프로토콜과 같은 층위)와 **에피소드 LOGO 40폴드**.
`alpha` 와 `k` 는 학습 폴드 **안쪽**의 에피소드 군집 CV 로만 고른다. CI 는 에피소드 40개 복원추출 2000회.


### 천장을 먼저 쟀다

* **혼합 상태는 문턱 잡음이 아니다.** 혼합 50개에서 `min(안전 open_min) − max(위험 open_min)` 중앙값이
  **+0.0077 m**이고, 0.04 m 문턱 ±0.002 m 안에서만 갈리는 상태는 **0개**다. 진짜 행동 차이다.
* **그런데 라벨 잡음이 하필 거기 몰려 있다.** 중복 분기 불일치 5건 중 **3건이 혼합 상태 안**이다 —
  P(불일치|혼합) 6.0% 대 P(불일치|비혼합) 0.25%, 약 24배. 쌍의 ~12%가 동전던지기라면 상태 내 AUROC 의
  천장은 1.0 이 아니라 **대략 0.82–0.85**다 (3/50 이라 이 추정의 CI 도 넓다).
* **선택 여유폭은 2.7 %p 뿐이다.** 혼합 상태가 전체의 5.9% 라서 완벽한 랭킹도 전체 C1 을
  13.3% → 10.6% 까지만 내린다. 그리퍼 스칼라가 이미 그 중 69% 를 먹었다.
* **그래도 쫓을 만한 신호는 있었다.** 상태 내 phi 편차의 유효 랭크는 **39**(PC1 3.8%, PC1–20 63%)이고,
  그 PC1 은 그리퍼 명령과 거의 무관하다(**r = −0.03**). phi 는 스칼라가 못 담는 행동 정보를 담고 있다.
  남은 질문은 "있느냐"가 아니라 "546쌍/31군집으로 꺼낼 수 있느냐"였다.

| Ranking `raw` [과제] | 0.716 [0.653, 0.779] | 11.7% | −0.077 [−0.155, +0.010] |
| Ranking `resid` [에피소드] | 0.586 [0.502, 0.664] | 12.6% | **−0.207 [−0.307, −0.100]** |
| Ranking `resid` [과제] | 0.536 [0.456, 0.615] | 12.5% | **−0.258 [−0.367, −0.140]** |
| 무작위 | 0.522 [0.443, 0.610] | 12.8% (기대 13.3%) | — |

**어느 변형도 그리퍼 스칼라를 넘지 못했다.** 가장 좋은 `pca` [에피소드] 조차 −0.023 [−0.100, +0.058] 로
구분되지 않고, 점추정은 아래에 있다. 선택 후 C1 발생률은 전부 11.4–11.7% 로 뭉쳐 있다
(오라클 10.6%, 무작위 13.3%).

**`resid` 는 무작위 근처로 주저앉는다** — 과제 분할 0.536, 에피소드 분할로 학습 데이터를 최대한 줘도 0.586.
그리퍼 baseline 대비 −0.258 / −0.207 로 **유의하게 나쁘고**, 선택 C1 도 유의하게 올라간다
(+1.06 %p [+0.00, +2.14], +1.17 %p [+0.12, +2.24]).

**이것은 최적화 실패가 아니다.** in-sample 진단(같은 쌍으로 학습·채점)에서 `raw` 와 `resid` 모두 **1.000** 이다 —
1024차원은 546쌍을 완벽히 분리한다. `pca`(k=40)는 0.868. 그리고 lbfgs 수렴 실패는 **0 / 11,751 회**다.
따라서 과제 LOGO 의 0.536 은 전부 **일반화 격차**다.

### 읽는 법

phi 의 상태 내 편차에서 그리퍼 명령 방향 **하나**를 빼면, 이 표본 크기에서 일반화되는 신호가 거의 남지 않는다.
Stage A 의 "head 와 그리퍼가 구분되지 않는다"는 더 강한 형태로 반복된다 — 질문을 상태 내로 바꿔 직접 학습해도
결과는 같다.

다만 이것은 **phi 에 그리퍼 밖의 신호가 없다**는 뜻이 아니다. 유효 랭크 39 와 r = −0.03 은 그 반대를 가리킨다.
정확히 말하면 **546쌍 / 31군집으로는 그 신호를 꺼낼 수 없다**. 두 진술은 다르고, 구분해서 적는 편이 낫다.
표본을 늘리려면 혼합 상태를 늘려야 하고(현재 5.9%), 그건 보상이 아니라 **표집 분포**의 문제다.

**Stage C 는 다시 돌리지 않았다.** 재실행 조건은 "새 head 가 그리퍼 baseline 을 넘을 것"이었고 넘지 못했다.
(`data/stagec` 에는 `phi` 가 저장돼 있지 않아 재수집 없이는 새 head 를 거기서 채점할 수도 없다.)
Stage C 의 무작위 λ10/λ30 대조군이 인과 기준선으로 그대로 남는다.

## 결론

1. **C1 head 의 기울기는 부호 있는 인과 신호를 담고 있다.** 내려가면 C1 이 줄고(−0.95 pp) 올라가면
   늘어난다(+1.42 pp). 부호를 뒤집은 차이 −2.37 pp [−3.96, −0.95] 는 무작위 섭동이 만들 수 없는 대비다.
2. **그러나 같은 보폭의 뒤섞은 방향보다 낫다고 말할 수 없다.** λ10 에서 −0.59 pp [−1.45, +0.23],
   λ30 에서는 무작위 쪽이 오히려 낫다(구제율 27.3% vs 18.2%). 이득의 대부분은 "chunk 를 정책이 선호하는
   자리에서 밀어냈다"는 일반적 효과다.
3. **점수는 많이 움직이는데 세계는 조금 움직인다.** 위험 점수를 3.49 logit 낮춰도 C1 발생률은 2.37 pp
   줄어든다. 분류기를 그 분류기가 학습한 분포 밖에서 최적화할 때 나타나는 전형적인 모습이다.
4. **감시자가 곧 보상은 아니다.** 같은 head 가 미학습 task 에서 0.885–0.930 으로 "지금 위험하다"를 맞히면서,
   "그러면 대신 무엇을 하라"에 대해서는 무작위 섭동만큼의 정보밖에 주지 못한다. Stage A 가 이유를 말해 준다 —
   상태를 고정하면 이 head 가 읽는 것은 사실상 그리퍼 명령 하나다.
5. **질문을 바꿔 직접 학습해도 같다 (Stage D).** 상태 내 판별로 학습한 선형 head 는 어느 변형도 그리퍼
   스칼라를 넘지 못했고(최선 −0.023 [−0.100, +0.058]), 그리퍼 방향을 제거하면 무작위 근처로 떨어진다
   (−0.258 [−0.367, −0.140]). in-sample 1.000 · 수렴 실패 0/11,751 이므로 최적화가 아니라 일반화의 문제다.
   정확히는 **546쌍 / 31군집으로는 꺼낼 수 없다**는 진술이지, phi 에 신호가 없다는 진술이 아니다.

### 다음에 할 수 있는 것

* ~~상태 내 판별로 직접 학습한 head.~~ → **Stage D 에서 했다. 넘지 못했다.**
* **표본을 늘리는 쪽이 먼저다.** Stage D 의 병목은 모형이 아니라 혼합 상태 50개 / 쌍 546개 / 군집 31개다.
  `sensitivity.py` 를 더 많은 init·task 로 돌리면 선형적으로 늘어난다. 라벨 잡음이 혼합 상태에 24배
  몰려 있으므로(천장 0.82–0.85), 분기를 2회 반복해 불일치 후보를 떨구는 편이 같은 비용 대비 낫다.
* **후보 다양성 쪽.** 위험한 호출의 80% 는 후보 8개 전부가 C1 을 일으킨다. 보상을 고치는 것보다
  표집 분포를 넓히는 쪽(온도, inversion, 더 큰 λ 를 쓰되 성공률을 함께 보기)이 천장을 올린다.
* **탐지기는 방아쇠로.** 0.885–0.930 은 "언제 개입할지" 에는 충분하다. 개입 내용은 다른 데서 와야 한다
  (중범의 recovery 쪽과 붙는 지점).
* **성공률은 아직 측정하지 않았다.** Stage C 는 C1 발생률만 본다. guidance 가 C1 을 줄이면서 과제를
  망가뜨리는지는 닫힌 루프 rollout 이 필요하다 — 다만 위 결과를 보면 그 전에 보상 쪽을 먼저 고치는 게 낫다.
